# คู่มือสาธิต

## ก่อนนำเสนอ

1. เติมชื่อและรหัสจริงใน Proposal และสไลด์ ตรวจเวลาที่อาจารย์กำหนด
2. เปิด `run.bat` หรือรัน `.venv\Scripts\python.exe -m streamlit run app.py` แล้วเข้า http://localhost:8501
3. เปิดหน้าวิเคราะห์และวิเคราะห์ภาพหนึ่งครั้งก่อนเริ่ม เพื่อโหลดโมเดลเข้าสู่หน่วยความจำ ใช้ป้ายข้อมูลทดสอบเพื่อไม่ปะปนสถิติ
4. ทดสอบกล้องจริงด้วยผู้ใช้เองและตรวจสิทธิ์เบราว์เซอร์ หากกล้องไม่พร้อมให้ใช้ Upload
5. เปิดสไลด์ PowerPoint และสำรองภาพหน้าจอใน `assets/screenshots` ไว้ ข้อมูลภาพสำรองจาก QA ต้องอธิบายว่าเป็นรอบทดสอบ

## ลำดับสาธิตประมาณ 2 นาที

| ลำดับ | การกระทำ | สิ่งที่ควรสังเกต |
|---|---|---|
| 1 | เปิด Home แล้วกดเริ่มวิเคราะห์ | ตัวเลขอ่านจากฐานข้อมูลจริง |
| 2 | เลือก `data/samples/paper/paper_1875.jpg` | ภาพตัวอย่างถูกต้องก่อนกด Analyze Waste |
| 3 | กดวิเคราะห์แล้วรอจนขึ้นว่าบันทึกผลแล้ว | ประเภท คะแนน คำแนะนำ และเวลา |
| 4 | เลือกภาพแบตเตอรี่ `data/samples/battery/battery_268.jpg` | รอภาพเปลี่ยนก่อนกดปุ่ม ผลเป็นคนละ event |
| 5 | เปิด Dashboard | หากเลือกป้ายทดสอบไว้ ตัวเลขจะไม่รวมรายการนั้นตามที่ออกแบบ |
| 6 | เปิด History รวมข้อมูลทดสอบถ้าจำเป็น กรอง Paper แล้วส่งออก CSV | CSV ควรตรงกับตัวกรองและเวลาเป็น UTC |

ภาพสองภาพนี้เป็นตัวอย่างจากชุดประเมินที่ใช้สาธิตการเชื่อมระบบ ไม่ควรนำการสาธิตสองภาพมาสรุปความแม่นยำทั้งระบบ

## แผนสำรอง

- โหลดโมเดลไม่สำเร็จ: ตรวจ `models/clip` และรัน `scripts/download_model.py` ล่วงหน้า ไม่มีผล AI จำลองทดแทน
- เครื่องสาธิตไม่มี dependency: ติดตั้งด้วย `setup.ps1` ก่อนวันนำเสนอ อย่าย้าย `.venv` จากเครื่องเดิม
- เว็บไม่เปิด: ตรวจ terminal หาก port ไม่ว่าง ใช้ `--server.port 8502` แล้วเปิด port ที่ตรงกัน
- กล้องไม่พร้อม: ใช้ไฟล์ภาพแทนและระบุว่ายังทดสอบกล้องไม่ผ่าน
- demo สดมีปัญหา: ใช้ภาพ result และ dashboard_data ที่เป็นผล QA จริง พร้อมบอกว่าเป็นผลรอบทดสอบที่บันทึกไว้

## สิ่งที่พูดให้ตรงกับหลักฐาน

มี Customization ด้วย prompts และกติกา ยังไม่มี fine-tuning น้ำหนัก ผล 88% มาจาก 50 ภาพตัวอย่าง เก็บผลการวิเคราะห์แทนปริมาณรีไซเคิลจริง และยังไม่มี user feedback หรือ public deployment
